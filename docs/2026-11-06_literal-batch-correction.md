## 修正

仍使用现有 ff_edit，已知的同文件独立修改优先一次提交：

```json
{
  "path": "src/config.ts",
  "match": "literal",
  "steps": [
    {"find": "timeout: 1000", "replaceWith": "timeout: 2000"},
    {"find": "retries: 1", "replaceWith": "retries: 3"}
  ],
  "reason": "调整请求超时和重试"
}
```

支持 1–50 个匹配对，全部定位原始字节快照。每项须唯一匹配；重叠、缺失匹配、矛盾操作或预算超限都拒绝整批写入。所有变更只有一个提交、审计及回执，保留 BOM、混合换行和字面量美元文本。步骤顺序可以不同于源码顺序，回执行号基于最终文本计算。

顶层单项简写继续支持；replaceAll 保持为单一模式的全局替换，不与 steps 混用。默认 block、行号操作、符号编辑仍保留。依赖前一步结果才能决定的操作仍应分开执行，不能强行合批。参数卫生现在允许 match 依赖 find 或 steps，同时移除严格 schema 自动补齐的无意图空值。

指导语和工具描述把批量编辑放在单项简写之前。没有增加新工具，没有禁止必要的单项调用，也没有增加每次调用的劝导回执。

## 等价工作量离线计量

`scripts/measure-edit-batching.mjs` 创建 3/10 个独立修改，比较逐项调用与一次批量调用。两条路径结果 SHA-256 相同；计入所有请求参数及完整回执；本样本无需续页，diff 均 complete。使用 o200k_base：

| 修改数 / 回执 | 单项调用数 → 批量 | 文本路径 Token：逐项 → 批量 | 结构化值路径 Token：逐项 → 批量 |
|---|---:|---:|---:|
| 3 / summary | 3 → 1 | 333 → 213 | 690 → 366 |
| 3 / diff | 3 → 1 | 731 → 367 | 1,247 → 575 |
| 10 / summary | 10 → 1 | 1,110 → 563 | 2,310 → 828 |
| 10 / diff | 10 → 1 | 2,728 → 843 | 4,484 → 1,176 |

文本路径为参数加工具文本，结构化路径为参数加 JSON 序列化值，两者是不同消费路径，不能相加。此处不含模型推理、PTC 程序包装、完整请求历史、缓存成本或收费；不声称线上同等比例节省。

新增批量模式的说明有成本：安装版 SDK 的 full 插件投影加引导，原生从 4,916 到 4,988 Token，PTC TypeScript 从 6,740 到 6,811，Python 从 7,868 到 7,939。接受这 71–72 Token 的增长以恢复合批能力；不再用提示词必须每次下降作为替代工作流验收的标准。
